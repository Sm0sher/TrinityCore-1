## Почему составная внешность пока не стала массовым исправлением

Прототип ядра передавал исходное тело, настройки лица и 11 слотов одежды через
штатный `SMSG_MIRROR_IMAGE_COMPONENTED_DATA`. Клиент запрашивал профиль, сервер
его отправлял. В игре получилось белое тело: необходимые исходные текстуры
кожи и одежды были перечислены в Root, но отсутствовали локально. Проверка
только наличия FileDataID в каталоге недостаточна для подтверждения отображения.

Затем проверен отдельный прототип с исходной готовой текстурой Classic:
лицо и тело отображались цветными, возврат исходной модели после GM demorph
работал. Итоговый пакет использует полностью нативные современные записи,
поэтому экспериментальный C++ и все созданные им таблицы, профили, временные
hotfix-записи и запись обновления удалены из рабочей установки. Исходные NPC
при этой очистке не удалялись. Исследование сохранено вне Git в каталоге аудита.

Оценка «568 кандидатов» в предыдущем отчёте означала наличие базовых
ресурсов в каталоге при исключении готовой текстуры. Она не подтверждала
наличие всех локальных слоёв для сборки внешности. Это число не засчитывается
как исправление.

## Проверка всего остатка

Проверены все 877 исходных шаблонов на наличие нативного набора записей с
эквивалентными ссылками на тело, расширенную внешность, текстуры и эффекты.
Полные наборы найдены для трёх восстановленных NPC. У остальных не найден
полный такой набор в проверенных данных; это не доказательство невозможности
восстановления другими источниками.

Для всех исходных вариантов Classic собрана консервативная опись **6470**
уникальных прямых файловых зависимостей:

| Состояние | Файлов |
|---|---:|
| Локально читается префикс | 585 |
| Есть в Root, но локальное чтение недоступно | 4938 |
| Нет в активном Root | 947 |

**Это не готовый список докачивания.** Опись включает альтернативные готовые
текстуры и плоские слои одежды, которые могут не требоваться при использовании
готового наряда. Для каждого NPC сначала нужно определить фактически
используемую цепочку. Три восстановленных NPC используют современные нативные
ресурсы, а не весь набор старых файлов из этой описи.

У остатка также сохраняются ограничения из предыдущего аудита: нет полного
исходного набора записей либо подтверждённых размеров. Нулевые ссылки вместо
нужных ресурсов и общие размеры 0,389/1,5 не применялись. Если нужного файла
нет в клиенте и нет подтверждённого эквивалента, SQL и серверный пакет внешности
не заменяют этот файл. Такой случай остаётся нерешённым, а не скрывается из лога.

## Проверки и воспроизведение

Итоговые 12 строк применены дважды в изолированной БД на обычном рабочем ядре.
Получено ровно три ожидаемых исчезнувших сообщения и ноль новых. Рабочий
перезапуск повторил результат; порты bnetserver/worldserver открыты.
После рабочего перезапуска все три DisplayID проверены в игре на неподвижной
цели через GM morph: видны тело, лицо, одежда и портрет. Затем выполнен demorph,
исходная цель восстановлена. Вход персонажа на клиенте 70959 успешен.
Проверки игровых сценариев, квестов и добычи для этих трёх NPC не проводились.

SQL, точные строки и источники: `contrib/forever-audit/70959-native-appearance-877/`.

применением нужно проверить свободные Id в hotfix_data: пакет не выделяет их
динамически. Уже установленная рабочая БД повторного применения не требует.
